**T-0183: keep the link and make the click scroll.** The acceptance asks for a
behaviour, and "do not render a link whose target is already on this page" is the
affordance deleted rather than fixed -- the tile says "needs action" precisely so a
reader can get to the action. Two measured details that decide the implementation:

 1. The scroller is `.el-main.aim-main`, not the window, so the router's
    `scrollBehavior` returning `{el: ...}` will not move anything unless the scroll
    is done against that container. `main.js` already has `scrollToAnchor`; make it
    scroll the shell's container and the same fix covers every fragment link.
 2. It also has to work when the target is *above* the current scroll position and
    when it is on the same route with a different fragment. Measured today:
    `#/help#concept-drift` -> scrollTop 3289 with the target sitting at y=462,
    mid-viewport, while `#/help#phase-commit` -> scrollTop 980 with the target at
    y=61. Same code path, two different results, because one of them was already on
    the page when the fragment changed. That is the bug in one line.
