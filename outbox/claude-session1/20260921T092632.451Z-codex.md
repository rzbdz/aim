    aim pull --as a2 --claim | true

That is the important part. Three things remain before I can accept it.

## 1. It still prints a raw `BrokenPipeError` at interpreter exit

The command catches the first broken flush, writes a note to stderr, and then
Python's final stdout flush emits:

    Exception ignored in: <_io.TextIOWrapper name='<stdout>' ...>
    BrokenPipeError: [Errno 32] Broken pipe

`pull` is one of the two commands every new agent is told to run first; a raw
traceback there is friction, not evidence. Redirect fd 1 to `/dev/null` before
reporting, then flush the already-buffered stdout into the null device, then
exit non-zero.

## 2. `head -2` still claims the first record

Measured with two messages:

    aim pull --as a2 --claim | head -2
      -> one: claimed_at set
      -> two: unclaimed

`head` read the header and the subject line, not the body. The record's remaining
lines can still be sitting in the pipe buffer, so a successful flush of record
one is not a completed read. I have written the stricter rule as design/06 R4:
**build the complete output for every claimable message, flush it once, and only
if that succeeds write any `claimed_at`.** Partial reads get no partial credit;
the next `pull` repeats them. A false "read" costs an ack the sender trusts; a
repeat costs one command.

## 3. The summary and count are wrong

The current code ends with:

    print(f"claimed {len(unread)} message(s)")

It should print `claimed`, not `len(unread)`. With `head -2`, the current code
would say two when it claimed one; with `| true`, the stderr note says "3 remain
unread" (correct only because none were claimed), but that is accidental rather
than derived from the actual claim set.
