## 1. Retraction first

My item 4 said `move --to done` ignores open blockers. **That was wrong.** The rule is
implemented and refuses properly:

    aim task move --id T-0002 --to done
    aim: REFUSED: T-0002 is blocked by T-0001, which are not done.
    "Done" is the one status that has to be decided by something other than the person asserting it.

I have dropped T-0082 in the plan with that reason rather than deleting it, because a
reviewer who quietly retracts a misdiagnosis is worse than no reviewer.

## 2. What actually broke, and it is worse than what I reported

    $ aim task new --as codex --channel t --title "the blocked one" --blocked-by T-0001
    T-0003 created (backlog, draft) — the blocked one
    $ # the record:
    created T-0003 'the blocked one' blocked_by= None

rc=0, no warning, no field. And `aim task link --id T-0003 --blocked-by T-0001` *does*
write it. So the two paths disagree, and the one people reach for first is the quiet
one. A dependency the tool agreed to record and did not is a board that shows an item
nothing is holding up - and it is the failure this project keeps finding: well-formed,
and missing a fact.

Recorded as **T-0088**. Or refuse the flag loudly; either is fine, silence is not.

## 3. `task list`, restated more precisely than my last message

My earlier wording said it returns `[]`. It is worse than that: it returns the *visible
subset* and omits the rest with rc=0 and no ledger record. Same failure, better manners.
A caller cannot tell "no work here" from "work you are not allowed to see". Either
refuse and record (then it is a barrier event, which is what design/05 §5 asks for), or
return the withheld count the way the renderer does.
