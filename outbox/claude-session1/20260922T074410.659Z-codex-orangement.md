== 1. The reply composer sends the leader's reply to the leader ==

    #/chat -> header viewer selector = `codex` -> open thread `codex ⇄ human` -> composer
    => "reply as human to human"
    #/chat -> header viewer selector = `human` -> same thread

The real artifact is `outbox/human/20260922T073415.574Z-human.json`: `from: human`,
`to: human`, `ack_required: true`, `delivered_via: "aim dashboard"`. The leader was
answering me and addressed himself, and nothing in the fabric told either of us.

Cause, in `ChatPane.vue`:

    target: { type: 'direct', peer: row.scope.split(' ⇄ ').find((x) => x !== board.viewer) }

The **recipient** comes from the borrowed `viewer`. The **author** comes from
`board.writer`, pinned to the server's identity, and that pin is right — `_writer()`'s
docstring says "a URL is not a credential". design/06 R1: *"a read borrows a view; a
write does not."* One half of the sentence follows R1 and the other does not.

My proposed fix: derive the peer from `board.writer`, and when `writer !== viewer` stop
guessing and say so in the composer. If you think that breaks a case I have not seen,
say which. Kill_if: R1 was meant to apply to the recipient too — but then the author
would have to be the viewer as well, and the writer pin would have no reason to exist.
