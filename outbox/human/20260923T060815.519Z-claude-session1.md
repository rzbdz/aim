## What it does, in one paragraph

`aim depart --as <you> --reason "<why>"` writes `departed_at`, `departed_session` and
`departed_reason` onto your registry record and appends a `departure` entry to the
same `registration_events` list `register --force` already builds. From that moment
every verb refuses that id, `class=barrier`, through the one gate every verb already
passes through (`resolve_actor`) — so it is the whole feature in one place rather than
36 call sites. Two ways back: `aim depart --as <you> --return`, or `aim register
--force`, which clears it as part of taking the id over. Both are named in the refusal
text, and group B of the test asserts that both actually run, because a refusal that
names a remedy which cannot run is the exact failure that suite exists to catch.

## The honest half, which is why this is not a complete answer

**It is self-declaration. A session that crashes cannot call it.** The case that
prompted it — sessions that died without saying so — is precisely the case a flag
cannot cover, and it needs a witness *outside* the session: a `last_seen` written by
`resolve_actor`, or treating `outbox/<peer>/*.json` as a heartbeat. That witness is
not in this commit. The verb's own `--help` says so, in the docstring and in the
description, because a verb that is oversold is worse than no verb:

> This is self-declaration, not liveness: a session that crashes cannot call it, so it
> covers orderly exits and nothing else. The case that prompted the verb — sessions
> that died without saying so — needs a witness outside the session and does not have
> one.

## The card's own accept line, checked clause by clause

T-0253's accept line has four clauses. Three hold; the fourth does not, and it is not
a gap in the implementation — it is a thing no flag can do. I am not moving the card,
because it is codex's, and I would rather you see the mismatch than watch me close it.

| clause | verdict |
|---|---|
| `aim depart` exists and marks the registry record departed | **yes** |
| refused for an id that is not yours unless `--force` | **impossible, and said so.** This fabric cannot test "is this id yours": `register --session` is a free-text note, not an identity — T-0242 measures two live sessions on one id, and `tests/test_channel_project.py` measures the mirror. So anyone who can run `aim` can depart any id. What is *not* silent is who called: `departed_session` is the caller's own token, so a departure by the wrong session reads as exactly that in `registry.json`. That is written into the verb's docstring. |
| refused a second time | **yes** — a re-depart is a no-op that exits 0 and does not move the timestamp the refusal prints |
| the departed record is visible to a reader | **yes** — `registry.json` alone, one field, no deletion |

And the closing clause — *a reader given `registry.json` alone can tell which of the
six registered ids are still running* — holds for a departure that was **declared**,
which is the narrower thing it actually says and the only thing it can say. An id that
died without declaring is still indistinguishable from one that is idle. That is the
limit, not a bug, and it is the same limit the "every claude is dead" complaint runs into.
