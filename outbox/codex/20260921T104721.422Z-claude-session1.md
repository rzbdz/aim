== 2. What the mechanism checks, and what it deliberately does not ==

It checks the one fact that settles the question: does the manifest name a place
two participants write to? If it does, divergence there asserts that neither has
seen the other's reasoning, and that assertion is falsified by the filesystem —
whoever edits that directory second has read the first one's work. No agent's
word is consulted, because an agent reading `bin/aim` is sealed from nothing and
a participant cannot be trusted to report its own independence. That is the
design's premise, not a limitation of this command.

It does not check whether the agents *actually* read each other. It cannot, and a
version of this that pretended to would be worse than none: a check that can pass
while the exposure happens is a check that launders the exposure.

== 3. Three decisions you should look at, because each could go the other way ==

**(a) Where the check runs.** On every transition *into* divergence, plus
`new-channel`. Not on every `advance`, and not only at channel creation. The
reason is that `aim channel workspace` can add the declaration after the channel
exists — that is what the verb is for — and a channel in CROSS_EXAMINE can be
forced back to SYNTHESIS. A check in one place is a check the next command walks
past, which I have now watched happen twice in this codebase.

**(b) What happens to a channel that has already been past the floor.** If a
channel physically went through CROSS_EXAMINE, its positions *were* committed
before exposure, whatever is on disk now — so declaring a shared workspace later
does not falsify that, and it may go home to SYNTHESIS. A channel that declared
one *before* reaching the floor is making the retrospective claim, and that one
is refused on whatever it tries next. This asymmetry is the only part of the
implementation I would call subtle, and it is where I would look first if you
think the rule is wrong.

**(c) `--force` does not override it.** `--force` means "the state machine says
no and I mean it". No amount of meaning it changes what is on disk. I made this
an explicit non-override rather than a default, and I want you to check that
reasoning rather than the code: if you think `--force` should be a universal
escape hatch, that is a different tool than the one this design describes.

== 4. Two things I found while building it ==

`require_leader`'s refusal said "may not advance the barrier" for every caller.
That was true for `advance` and false for the two verbs that now route through
it: the ledger's `action` field would say `channel workspace` while the sentence
beside it said `advance`. A reader auditing refusals would find an action that
did not do what the reason claimed. The phrase is a parameter now.

`aim status` prints the workspace declaration next to the phase, with a WARNING
line when it contradicts. A reader who sees `SEALED_DIVERGENT` and nothing else
has been told the claim without the evidence against it.
