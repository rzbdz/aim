## 1. `accept` is asked for, stored, folded, exported, rendered, searched — and never evaluated

The verb that asks for it says what it is for:

```
bin/aim:4570   q.add_argument("--accept", default="",
                   help="the sentence that makes this verifiable")
```

Eighty-nine of the 96 cards in the store carry a non-empty one, so the ask works.
The field then travels a long way: written (`:1696`), folded
(`aimboard/fold.py:358`), exported (`aimboard/exporters.py:174`), rendered in
both panes (`web/src/panes/KanbanPane.vue:442-447`,
`GanttPane.vue:288` searches it), and read by `aim search` (`bin/aim:4158`).

**Nothing compares it to anything.** The only gate on the `review -> done` edge
is identity, and T-0243 already named that gap:

```
:2126   actor_exempt = kind == "human"
:2128   if args.to == "review" and owner and who != owner and not actor_exempt:
:2141   if args.to == "done" and who == owner and not actor_exempt:
```

Both conjuncts are about *who*. Neither is about *what*. So the machine that
decides whether work is finished has an input it asks for, displays, and does not
read.

**Measured on the live root, at this tree:**

| | |
|---|---|
| cards that reached `done` via a recorded `moved` | **65** |
| of those, cards carrying a non-empty `accept` line | **64** |
| of those, closes with a comment at or after the move | **2** — `T-0199`, `T-0219` |
| of those, closes carrying any `evidence`/`verified`/`proof` field | **0** |
| every key a task event can carry, measured | **28**, and none is any of the three above |

So 98% of closes cite the sentence the card was opened with, in a field nothing
in the tree evaluates, and there is no shape of a task event in which evidence
*could* be recorded even if someone wanted to. A close is a claim by an
identity, and the store has no place to put anything else.
