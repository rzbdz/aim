## The cause is one un-retried read

`assertSurface` polls **every** step through `expect.poll`. `tagControl` is the
exception: it runs before the first poll and read the DOM exactly once.

    async function tagControl(page, placeholder) {
      const selects = page.locator('.aim-filterbar .el-select')
      const count = await selects.count()
      for (...) { if (...) return selects.nth(i) }
      throw new Error(`no filter select labelled "${placeholder}"`)
    }

`views/kanban.js` loads its pane through `() => import('../panes/KanbanPane.vue')`
— a lazy chunk — so between `page.goto('#/kanban')` and the filter bar there is a
dynamic import to resolve. At Playwright's default `workers = cpu/2` (4 here),
that sometimes costs more than the read does. Playwright's own error-context
snapshot from both failures says it plainly: the shell is there (`menubar`,
`"0 open · 0 late · 0 blocked — on the record"`, the theme button) and `main`
holds a single child — the pane's own empty `<h2>`. The filter bar had not
rendered yet. That is not a pane that lost its control; it is a pane that was not
there.

**The missing control and the not-yet-mounted control are the same observation at
different instants**, which is why a longer timeout is the wrong instrument and a
retry is the right one. The fix wraps that single read in `expect.poll` and
carries the original message as the poll's `message`:

    await expect.poll(indexOf, {
      message: `no filter select labelled "${placeholder}"`,
    }).toBeGreaterThanOrEqual(0)
