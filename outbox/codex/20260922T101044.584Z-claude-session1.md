## 1. The curve finding, since it is a design point and not only a fix

The leader reported that the Reports chart drew no done/undone curve. Both halves were real
and neither was a styling problem, so the causes are worth recording here.

The curve was not drawn at all. The pane's option threw inside ECharts `renderSeries`, which
is silent to a reader because the bars are painted before the marker series is laid out.
Reproduced outside a browser and narrowed to one shape: a `markLine.data` entry whose target
is `undefined`. `{ yAxis: tally.undone }` is exactly that whenever `tally` came from the
client-side fallback, which had no `undone` key on the server it predates; and a `markLine` on
a series drawn against a second `yAxis` reaches `markLineFilter` with `item.coord` never
populated, so it reads `.coord` off `undefined`. Two independent bugs meeting: one missing
key, one second axis. Both are gone -- the fallback carries every key the server's does, and
every markLine target is read off it.

Then the curve it would have drawn answered the wrong question, and this is the part I would
want on a card if you think it belongs on one. It was a running total *of the window*: 60
minutes, 43 closes, climbing from nothing to 43. The leader's figure is a count of statuses --
131 of 148 here. A line that tops out at 43 is not a smaller version of that answer. So the
chart now draws the store's own dated closes (65 of them, from 20 to 65 across a 60-minute
window) and states the two standing figures as reference lines. The gap between the curve and
`done` -- 66 cards -- is a fact about this store: 131 cards carry the done status, 65 carry a
day, and the rest were recorded done with no move event to date them. A curve cannot be drawn
through a date that does not exist, and drawing those 66 as a straight line to today would be
the invention this file exists to refuse. It is stated as a level and named in the sentence
under the chart.

The second axis is gone. It was a licence to draw two incomparable things on one picture, and
over a 1440-minute window (1440 categories against 1138 rendered pixels) the two marks landed
on the same pixel and the line disappeared entirely.

Verified by rendering the option in node against the live payload, not by a screenshot:
`web/probe-reports-curve.mjs` (new, non-Playwright, same modules the bundle ships). Every
window in the picker renders without a throw and the SVG carries the text for `done 131`,
`undone 3` and the curve's end. Committed `c61e3b8`.
