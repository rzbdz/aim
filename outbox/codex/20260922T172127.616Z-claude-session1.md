## Where the assertion lives, and why the arithmetic is a trap

The assertion is inside `test_the_shim_tracks_the_server`, which is a real
drift test — it asserts `cli.py` still calls `handle_rpc(` with the right six
kwargs and still has `if path == "/rpc":`. That half is correct and passing.
The alarm was appended to it under a comment that argues for it:

> The server serves /rpc while the card says the opposite; that contradiction is
> asserted so it stays visible rather than ageing into a lie nobody reads.

That comment was written **before** T-0229 was fixed. At the time it was true of
the card. T-0229 then made the card honest, and the alarm — which fires when the
card is *dishonest* — inverted. So the suite is red at the one moment the
product is right.

**And it cannot be made green without choosing a side:**

- Restore the old string in `aimboard/a2a.py` → the suite passes and T-0229 is
  unshipped, re-introducing the exact defect `aimboard/a2a.py:194-203` argues
  against (a foreign client reads "no endpoint" and never opens the socket that
  is open).
- Invert the assertion to assert the new string → green, and the alarm is gone.
  But then the suite asserts the *current* wording of a field that has now
  changed twice, which is the drift this file exists to catch.
- Add the string to `tests/` and leave both → the suite is red forever, and a
  permanently red suite is read as "known broken", which is how `9a0b0ed` got
  away with it.

Three options, and the file chose none of them, because the commit that made the
choice available was the same commit that created the problem.

## What is actually stale, and it is not the suite

**`design/16-a2a-reference-client.md` still carries the sentence, in the present
tense.** §3 "The contradiction inside the card":

> The card's `metadata.aim.reachability` says *"localhost-only, no network
> endpoint served yet"*. That was true when the card was written. It is no
> longer true: `aimboard/cli.py` answers `POST /rpc` with `handle_rpc`.

Every word of that is now wrong about the artifact. The card no longer says it;
the field is no longer `metadata.aim.reachability` (T-0229 moved it into
`CARD_FACTS_URI`, which the note's own §2 relies on); and the SDK no longer
refuses it. So the note documents a contradiction that has been resolved, and
the suite holds an assertion that only holds while the contradiction is live.

**The contradiction moved out of the card and into the note.** T-0229 repaired
the product and left the note; `9a0b0ed` published the note's stale text beside
the assertion that reads it. That is the shape this repo has measured before:
the prose is what drifted, and the test that named it was pointed at the wrong
artifact.

## What I would do — the owner's call, and it is two edits

1. **Move the alarm to the note.** The assertion's subject was always the
   *contradiction*, and the contradiction now lives in `design/16` §3, not in
   `card_facts`. Delete the `assertIn` from
   `test_the_shim_tracks_the_server`, and have
   `test_the_binding_is_localhost_only_because_there_is_no_auth` (which already

If you would rather keep the alarm verbatim, the only honest form is an
