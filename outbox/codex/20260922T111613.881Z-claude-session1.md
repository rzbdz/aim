## 2. Four mechanisms that cost real time to find. Each is a trap for the next reader.

**(a) Playwright's JSON reporter is the only trustworthy reading of a marked test.** With `test.fail(true, ...)`, a test whose body now passes is reported by `status: 'unexpected'` and by the *line* reporter as `N failed`. A test that genuinely still fails is `status: 'expected'`. So `--reporter=line`'s failure count includes inverted markers, and reading it as "these are broken" is exactly backwards. `status === 'unexpected'` means **the card is done**.

**(b) A markLine whose target is off the axis is deleted, not clamped.** `markLineFilter` runs each entry through `coordSys.containData(item.coord)` and drops what does not fit — no error, no warning, the line and its label simply absent from the SVG. That is what was wrong with the Reports chart's `done` level: at a 60-minute window the axis topped at 70 and `done 139` was filtered out. Fix is `max: (v) => Math.max(v.max, ...)` on the axis. The related landmine: a `markLine.data` entry whose target evaluates to `undefined` makes `renderSeries` throw after the bars are painted — silent to a reader, fatal to every later series.

**(c) A spec that reports `status: 'unexpected'` may be red for a reason nobody wrote down.** `playwright` 1.63 reports "Expected to fail, but passed" when the body throws, not only when it succeeds — the error is that the *test* failed, so `test.fail` is not applied. `card-t0179-rebuild-chunk`'s third test is in exactly that state: it times out on `composer.fill(DRAFT)` because the board is read-only, which is not the defect its marker names. If you see an inverted marker whose body is visibly still broken, that is the mechanism, and the honest repair is to correct the marker's reason rather than delete the marker.

**(d) A canvas chart is invisible to a spec that probes the DOM for paths.** `web/src/plugins/charts.js:3` registers `CanvasRenderer` and only canvas. `card-t0188-gantt-seeds.spec.js` measures bars by selecting `path` elements with a non-transparent fill, so on `#/gantt` it selects Element Plus's own nine icon paths — measured on the live page: `.aim-sticky-head` holds 1 canvas (1138x714) and 9 paths, all `currentColor / el-icon ...`. `chart.marked === 0` is therefore not evidence that a seed bar is unmarked, and no fix to the pane can turn that spec green. The pane's mark is in the *option* (`barStyle`, `GanttPane.vue:232`, sets `fill-opacity 0.32` for a promise), so the acceptance is implemented and the probe cannot see it.
