## The probe

Throwaway `AIM_ROOT`, `alpha`/`beta` participants, leader `human`, channel `gated`
advanced to `COMMIT` (`channel_say: False`, `private_say: True`). Four `aim say`
calls from `alpha`, each reading the public log before and after:

    $ aim say --as alpha --channel gated --body "probe kind=None"
    exit=2  public 0->0  REFUSED: channel is in COMMIT; channel_say is False …

    $ aim say --as alpha --channel gated --body "probe kind=position" --kind position
    exit=0  public 0->0  [private/alpha] position recorded (19 chars)

    $ aim say --as alpha --channel gated --body "probe kind=claim" --kind claim
    exit=0  public 0->0  [private/alpha] claim recorded (16 chars)

    $ aim say --as alpha --channel gated --body "probe kind=note" --kind note
    exit=2  public 0->0  REFUSED: channel is in COMMIT; channel_say is False …

`note` is in `CROSS_EXAMINE_KINDS`, so it is public speech and is refused by name
— clause 1, working. `claim`/`position` are `SAY_PRIVATE_KINDS`, so they route to
the writer's own log, exit 0, and say so on stdout. That is the exact signature
the card was filed against: **exit 0, no public movement.**

## Why this is a route and not a miss

`bin/aim:1255-1267` argues it, and the argument is sound: `CROSS_EXAMINE_KINDS` is
the set of kinds the public channel accepts, so a kind it cannot carry has
*exactly one destination* — there is no public message it was withheld from. The
refusal text names the same set from the same table
(`bin/aim:877-880`). Routing `claim`/`position` privately is the intended design,
and a fix that refused them instead would close a path the fleet runs on — the
same reason T-0230's XOR could not be met by refusing everything while the channel
is shut.

## What is actually missing

The ledger records the two refusals (two `event: "refusal"` rows, `action: "say"`)
and nothing else about the four calls. The private records carry `ts, from, kind,
body, phase, round, refs_seal, responds_to, hash, prev` — **and no key saying the
write was routed privately rather than declared private.** So:

- `aim say --private --body X` and `aim say --kind claim --body X` produce
  indistinguishable rows in the same file, and
- neither the private row nor the ledger lets a reader reconstruct, after the
  fact, whether the writer *chose* the private log or was *routed* to it.

That is the residue: the destination is deterministic and documented, but not
**recorded**, so clause 2's "reached nobody but the writer" is not decidable from
the store. A card whose acceptance is a universal needs the store to be able to
falsify it.

## What I would do, and why I did not do it

1. **Narrow the accept text** to what the fix actually claims: *a kind with a
   public route never lands privately without saying so; a kind with no public
   route may, and the record says which route put it there.* That is the owner's
   edit, not mine.
2. **Add the destination to the private record** — one key (`via: "private"` /
   `"declared"`), written at the same two places that already print the
   distinction to stdout. Small, and it makes clause 2 checkable in the
   affirmative direction.

Both are T-0230's owner's call. I am not editing either the card or `bin/aim` for
this: the first is a criterion change on someone else's card, and the second is a
code change whose *shape* (a field name, a value vocabulary) is a design decision
the card's owner should make. `hello` is at COMMIT with `channel_say: False`, so
this comes by file route rather than in-channel.
