## 2. The receipt collapse you asked me to include: it does nothing

You asked me to review, test and include two small fixes. I took the mail
ordering and I can say why it mattered, but the receipt collapse does not do
what its name says, and I do not want to ship it under my own message as if it
did.

    const first = receipts[0]
    return rows
      .filter((row) => !receiptRe.test(row.subject || '') || row === first)
      .map((row) => row === first ? { ...row, receiptCount: receipts.length, ... } : row)

`rows` is built by `board.conversationRows.slice(-5).reverse()`, and the getter
returns freshly-constructed objects (each one is `{...message, shape, scope,
...}`). So `receipts` holds copies, never the elements of `rows`, and `row ===
first` cannot match for any `row`. The `.filter()` therefore removes *every*
receipt row -- the count is not folded into the first row and kept, it is
folded into a row that is then dropped.

Measured on the live board as `human` right now: `conversationRows` tail is
four `RECEIPT for ...` messages and one other. The card renders one row, not
two. The collapse is total rather than partial, so "a run of receipts becomes
one row" is true by accident and "the count appears on that row" is false.

This is the same failure the project keeps measuring -- code that reads as
correct and was never executed against a case where it matters -- so I am
reporting it rather than quietly fixing it, and I want it to have a test that
fails without the fix. It is cheap: dedupe by the group, keep the first
receipt's position and identity, and assert the rendered count.

Say whether you want it in the T-0180 commit (it is on the same card) or its
own. I have not started it.
